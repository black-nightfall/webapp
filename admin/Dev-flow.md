# Admin 模块开发流程指南

## 新功能开发流程

### 1. 需求分析
- 确定功能边界和业务逻辑
- 确定涉及的实体和数据模型
- 确定与其他模块的交互方式

### 2. 后端开发流程

#### 2.1 创建领域实体
````
src/main/java/com/night/admin/domain/entity/
└── NewEntity.java
````
- 定义领域实体类
- 包含业务逻辑相关的属性和方法
- 遵循领域驱动设计原则

#### 2.2 创建持久化实体
````
src/main/java/com/night/admin/infrastructure/persistence/entity/
└── NewEntity.java
````
- 定义JPA实体类
- 添加数据库映射注解
- 定义表结构和关系

#### 2.3 创建Repository接口
````
src/main/java/com/night/admin/infrastructure/persistence/repository/
└── NewEntityRepository.java
````
- 继承JpaRepository
- 定义自定义查询方法
- 使用持久化实体类型

#### 2.4 创建领域服务
````
src/main/java/com/night/admin/domain/service/
└── NewDomainService.java
````
- 实现核心业务逻辑
- 依赖Repository接口
- 不直接依赖基础设施层实现

#### 2.5 创建DTO
````
src/main/java/com/night/admin/application/dto/
├── request/
│   └── CreateNewEntityRequest.java
└── response/
    └── NewEntityResponseDTO.java
````
- 请求DTO：接收前端数据
- 响应DTO：向前端返回数据
- 使用Lombok注解减少样板代码

#### 2.6 创建应用服务
````
src/main/java/com/night/admin/application/service/
└── NewApplicationService.java
````
- 协调领域服务操作
- 处理应用层事务
- 实现DTO转换

#### 2.7 创建映射器
````
src/main/java/com/night/admin/application/mapper/
└── NewEntityMapper.java
````
- 实现领域实体与DTO之间的转换
- 使用Builder模式构建DTO

#### 2.8 创建控制器
````
src/main/java/com/night/admin/interfaces/
└── NewEntityController.java
````
- 定义REST API端点
- 使用统一的[ApiResponse](file:///Users/peigen/Documents/dev/peigen/webapp/common/src/main/kotlin/com/night/common/dto/ApiResponse.kt)响应格式
- 实现参数验证和异常处理

### 3. 数据库迁移

#### 3.1 创建迁移脚本
- 在`infra/db/migration/`目录下创建新的迁移脚本
- 脚本命名格式：`V{n}.{n}.{n}__{description}.sql`
- 确保脚本与实体类定义一致

#### 3.2 示例迁移脚本
```sql
CREATE TABLE new_entities (
    id bigint PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name varchar(255) NOT NULL,
    description text,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now()
);
```

### 4. 前端开发流程

#### 4.1 定义TypeScript类型
````
frontend/src/types/
└── NewEntity.ts
````
- 定义与后端DTO对应的TypeScript接口
- 保持字段名称和类型一致性

#### 4.2 创建API服务
````
frontend/src/services/
└── newEntityApi.ts
````
- 实现与后端API的交互
- 使用统一的错误处理
- 遵循后端[ApiResponse](file:///Users/peigen/Documents/dev/peigen/webapp/common/src/main/kotlin/com/night/common/dto/ApiResponse.kt)格式

#### 4.3 创建功能组件
````
frontend/src/features/new-entity/
├── NewEntityList.tsx
├── NewEntityForm.tsx
└── index.ts
````
- 按功能模块组织组件
- 遵循单一职责原则
- 实现错误边界和加载状态

### 5. 模块间交互规范

#### 5.1 服务间调用
- 通过API端点进行服务间通信
- 不直接访问其他模块的数据库
- 使用异步通信模式

#### 5.2 数据共享
- 通过API共享数据
- 避免直接访问其他模块的内部数据
- 使用事件驱动模式进行异步通信

#### 5.3 依赖管理
- 避免循环依赖
- 通过公共模块共享通用功能
- 使用接口隔离模块间依赖
